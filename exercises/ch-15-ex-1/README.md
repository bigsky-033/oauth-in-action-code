# Chapter 15, exercise 1: proof-of-possession tokens

Run `./gradlew :exercises:ch-15-ex-1:run` or IntelliJ's
`org.oauthinaction.ch15ex01.completed.CompletedExercise.main()`. Authorize at
http://localhost:9000/, inspect the delivered key and fetch the resource. Stop
other exercises on ports 9000–9002 first.

AS generates a fresh RSA keypair per access token, stores only the public JWK and
returns the private JWK to the client with token_type PoP. The client signs a JWS
containing the access token, timestamp and HTTP method/authority/path, then sends
`Authorization: PoP <JWS>`. Resource uses the unverified token reference only to
introspect for its public key, verifies the signature, then checks bound request
components. `Proof` shows JWS/JWK framing around standard JDK RSA primitives.

This preserves the book's historical PoP format, not modern DPoP. The source makes
method/authority/path optional and does not validate timestamp freshness, replay,
headers or query parameters; those limitations remain explicit and tested instead
of being silently replaced by another protocol. Missing/invalid proofs and bare
Bearer tokens are rejected. Introspection is authenticated and never exposes the
private exponent. Access tokens are opaque and no refresh grant is added here.

`StarterExercise.main()` / `runStarter` leaves key-bound issuance, client signing,
and resource verification in three short TODO overrides. Individual entry points:
authorization variant, resource variant, client variant. AS-only storage is
`${java.io.tmpdir}/oauth-in-action/ch-15-ex-1/tokens.json`. Keys are generated by
the JDK, with no external key service/dependency.

`./gradlew check` covers complete PoP flow, independent keys, private/public key
separation, authenticated active/inactive introspection, wrong key/signature/token/
method/authority/path, bare Bearer rejection, historical optional/replay behavior,
starter gaps, state and assets on temporary ports/files.
